    How measurements work

    Every displayed claim is backed by a saved measurement.

    Python's role and what it can and cannot verify

    What Python checks: All four feasibility constraints (budget, deadline, capacity, insurance) are computed from the source record using exact arithmetic — no LLM involvement. The result is the authoritative audit passed to every agent.

    What agent claims are checked against: Each structured claim tuple (quote_id, constraint, result) is compared to the Python audit. Claims that contradict the audit are rejected and stored verbatim in claim_validation.rejected; only safe_text reaches the next agent.

    What the decision validator checks: The final option_id, total_cost_usd, and arrival_date must exactly match the Python recommendation. A wrong selection or invented explanation yields status = failed_validation — it is never silently passed through.

    What is not verified: Narrative prose quality, reasoning beyond the canonical explanation, real-world shipping feasibility, and the correctness of the model's general knowledge. Checks cover supplied facts only.

    Separating compression savings from run-to-run variation

    All branches share Ingestion and the protected source facts. Adaptive mode measures three workflows: full source with six LLM roles, compression alone with six LLM roles, and compression with Python tools. Short inputs keep four LLM roles; long inputs keep three. Every remaining LLM role receives the complete source. The difference_attribution field identifies how the comparison was made:

    • compression_routing_and_output_variation — compression and Python tools were used. The compression-only branch separates context savings from avoided agent calls and output changes. These total savings are not compressor-only savings.
    • paired_compression_and_output_variation — compression was applied; savings include both context reduction and natural output variation.
    • rejected_compression_cost_and_output_variation — the compressor ran but fell back to full context (invalid caveat coverage); its cost is still charged.
    • run_to_run_variation_no_compression — compression was skipped entirely; any token difference is pure output variation with no context reduction.

    When compression is skipped, no savings are reported. The "Token reduction" metric is set to "Skipped" rather than a number, to avoid attributing normal variation to compression.

    Validation failures and skipped compression

    Failed validation: If the model selects a wrong quote or uses an unverified explanation, the Decision report is replaced with FAILED VALIDATION: <failed_checks>. The pair status becomes failed_validation. These pairs are counted in failed_validation_pairs and reduce decision_accuracy.

    Skipped compression: Adaptive and Complete source apply the deterministic projection only when it is shorter; they do not predict a minimum token saving. Disabling adaptive compression also disables routing. The experimental Decision-focused mode uses a calibrated cost policy and falls back to the source when its LLM compressor omits required caveats; that call is still charged.

    Evaluation limits: Results are measured on a small set of fictional logistics quotes. They do not rank models for real-world tasks. Branch order alternates across repeats to reduce ordering bias. Standard deviation is only reported with two or more applied pairs.
